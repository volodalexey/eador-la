# План: порт Eador. Genesis с C++/Allegro 4 на Zig + raylib

## Команды

```sh
./tools/wsync.py from-wine-sav [--prfx PREFIX]       # одиночная игра → testdata/sav<ход>
./tools/wsync.py from-wine-hot [--prfx PREFIX]       # мультиплеер (hot seat) → testdata/hot<ход>
./tools/wsync.py from-wine-cmp [--prfx PREFIX]       # кампания → testdata/cmp<ход>
./tools/wsync.py from-zig-eador DIR [--prfx PREFIX]  # testdata/DIR → префикс
```

### Ключевые механизмы

**Ввод через pointer.** Модуль `input.zig` выдаёт за кадр:

- `Pointer { pos, down, pressed, released, primary/secondary, wheel }` в координатах виртуального экрана;
- на десктопе источник — мышь; на `Android` — touch 0 и жесты `raylib`;
- правая кнопка оригинала (подсказки, информация об объекте) на touch отображается в долгое нажатие;
- hover оригинала (подсветка, всплывающие подсказки) на touch показывается при удержании;
- кадровая очередь событий, чтобы короткий тап (press и release в одном кадре) не терялся, вызов напрямую `GetMouse*`/`IsMouseButton*` не делается;

**Графика.** Всё рисуется в `RenderTexture2D` 1024×768, затем растягивается на окно с сохранением пропорций. Color key magenta превращается в альфа-канал на этапе импорта. `draw_trans_sprite` / `draw_lit_sprite` / `set_trans_blender` заменяются явными параметрами (`alpha`, `tint`) при вызове отрисовки. Глобального блендера нет. Код, который работает с пикселями в CPU (флаги, гербы, маски, `getpixel` по провинциям карты), использует `Image` и после изменения загружает текстуру.

**Текст.** `.var` и `.txt` в оригинальноых ресурсах `cp1251`, он конвертируются в `UTF-8` при импорте.
Шрифт рисует по кодпоинту через таблицу Unicode → глиф cp1251 (`0x20–0xFF`).

**Данные и состояние.** Псевдомассивы `pFirstX + i` (с индексацией от 1) становятся слайсами в `Data` / `Game`.
Связи между сущностями хранятся индексами (`ProvinceId`, `HeroId`, ...).
Временные глобальные «регистры» (`iEvPlayer`, `MovePlayer`, ...) становятся параметрами функций или полями контекста сцены.
Константы `MAX_*` из `Globals.h` переносятся как есть.

**Сохранения.** Кодек `save/` описывает раскладку каждой 32-битной структуры явно (смещения, размеры, порядок полей из `GameMenu.cpp` и `Unit.h`).
Указатели при записи превращаются обратно в 32-битные значения, для соответствия оригиналу

**Ресурсы.** `eador-import` по каждому `.dat` пишет PNG/OGG и манифест «индекс → файл».
Код использует именованные константы вместо `datGUI[17]` (enum на каждый датафайл).
